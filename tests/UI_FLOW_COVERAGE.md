# План и статус UI-покрытия бизнес-потоков

Этот файл — журнал выполнения плана UI-регрессии. Он отделяет проверенные браузером сценарии от API-тестов и от ещё не реализованного покрытия. Все интеграционные тесты должны работать только на изолированной временной БД; Production не использовать.

## Приоритеты текущего прохода

По решению пользователя выполняются только пункты 1, 3, 4 и 5 исходного списка: стабилизация критического прогона; связность UI-фикстур; CRUD ключевых операций; пересчёты склада/оборудования и связанной экономики. Остальные пункты, включая расширение общего legacy-номенклатурного покрытия, пока отложены.

## Критерий завершения

- Все основные формы проверяют обязательные автоподстановки и фильтрацию связанных справочников.
- Создание, редактирование, удаление и восстановление проверены через UI для поддерживаемых операций.
- Сквозные тесты сверяют тонн-остатки, себестоимость, экономику затронутых сделок, аудит и SSE после обычных и задних изменений.
- Есть негативные сценарии: отсутствующая цена/привязка, неподходящий базис, нехватка остатка, пустая обязательная номенклатура, неполный откат.
- Полный набор выполняется в изолированной БД через `npm run test:critical-flows`; короткие профильные проверки доступны отдельно.

## Открытые пробелы, найденные при инвентаризации

- UI-фикстура заправки проверяет два warehouse-поставщика на одном базисе и правильный выбор второго склада; полная матрица складов, продуктов, цен и зарубежных ценовых цепочек всё ещё отсутствует.
- Зарубежная посредническая/банковская цепочка проверена на одном заказе и курсе; ещё не покрыты все сочетания валют, типов комиссии, ценовых индексов и пересчётов связанных сделок.
- Нельзя считать API-тест эквивалентом проверки выбора данных в браузерной форме.
- Причина риска с `nomenclatureId`: UI выбирает default после асинхронной загрузки справочника; если default отсутствует или ещё не загрузился, выбор остаётся пустым, а nullable-схемы/колонки допускают `null`. Серверные проверки создания и редактирования реализованы; интеграционно проверены создание/изменение мультипродуктового заказа ВС и legacy-строки перевозки. Общая логика сохраняет legacy-пустоту только при неизменном типе; в браузере подтверждён representative legacy-flow перемещения. Реальное legacy-редактирование остальных форм и UI-сценарий отсутствующего default остаются открытыми. Для последнего нужно подготовить состояние до начала UI-сессии: изменение DB-fixture внутри активной сессии не обновляет React Query cache детерминированно.
- Некоторые формы намеренно сохраняют пустую номенклатуру при редактировании legacy-записи с неизменённым типом. Это проверено браузером для перемещения; другие формы ещё нужно покрыть отдельно.
- Канонические ID/индексы и предзаполнение проверяются для опта, заправки, покупки-перемещения, зарубежной заправки и перевозочного черновика; остаётся проверить цены и восстановление выбора во всех остальных формах операций, если они используют те же селекторы.
- Для тарифов проверены три активных маршрута и отказ неактивного; остаются UI-CRUD тарифов, смена/удаление связей и выбор между несколькими доступными тарифами/перевозчиками.
- Полный UI-CRUD связанных договоров, базисов, тарифов и цен всё ещё не закрыт.
