# План и статус UI-покрытия бизнес-потоков

Этот файл — журнал выполнения плана UI-регрессии. Он отделяет проверенные браузером сценарии от API-тестов и от ещё не реализованного покрытия. Все интеграционные тесты должны работать только на изолированной временной БД; Production не использовать.

## Критерий завершения

- Все основные формы проверяют обязательные автоподстановки и фильтрацию связанных справочников.
- Создание, редактирование, удаление и восстановление проверены через UI для поддерживаемых операций.
- Сквозные тесты сверяют тонн-остатки, себестоимость, экономику затронутых сделок, аудит и SSE после обычных и задних изменений.
- Есть негативные сценарии: отсутствующая цена/привязка, неподходящий базис, нехватка остатка, пустая обязательная номенклатура, неполный откат.
- Полный набор выполняется в изолированной БД через `npm run test:critical-flows`; короткие профильные проверки доступны отдельно.

Сборы тестовых поставщиков отделены от поставщика базовой экономики, чтобы справочная фикстура не меняла ожидаемую прибыль сквозного сценария.

## Открытые пробелы, найденные при инвентаризации

- UI-фикстуры ещё не охватывают складские привязки нескольких поставщиков, все продуктовые цены и полные зарубежные ценовые цепочки.
- Заказ ВС из трёх продуктов покрыт API-тестом, но не браузером; зарубежные посредники, банковская комиссия и курсы не проходят вместе в UI-flow.
- Нельзя считать API-тест эквивалентом проверки выбора данных в браузерной форме.
- Большинство схем и колонок допускают `nomenclatureId = null`; обязательность для новых черновиков и финальных записей нужно проверить по каждому API-маршруту, затем закрепить тестами.
- Некоторые формы намеренно сохраняют пустую номенклатуру при редактировании legacy-записи. Это нужно отличать от нового создания и проверять отдельно.
- ОПТ, заправка и покупка-перемещение проверяют канонические ID/индексы и восстановление выбора; зарубежная форма и перевозка пока проверяют только доступность/автовыбор цен — сохранение ID/индексов и предзаполнение при редактировании ещё впереди.
- Для тарифов проверены три активных маршрута и отказ неактивного; остаются UI-CRUD тарифов, смена/удаление связей и выбор между несколькими доступными тарифами/перевозчиками.
- Полный UI-CRUD связанных договоров, базисов, тарифов и цен всё ещё не закрыт.
